# AUTORA

Окремий магазин автомобільних аксесуарів на основі можливостей doma. Нова вітрина та оформлення адмінпанелі. Node.js 22.12+ без зовнішніх залежностей для роботи сайту.

## Запуск

```powershell
npm start
```

Відкрийте http://localhost:3000. Для локальної адмінки скопіюйте `.env.example` у `.env.local` і задайте `ADMIN_PASSWORD` (8+ символів). Пароля за замовчуванням немає.

## Окремий репозиторій

Проєкт автономний; файли й Git-історію doma переносити не потрібно. Історію платежів та обидва PDF упаковано в `data/statement.enc` із шифруванням AES-256-GCM. У публічний GitHub потрапляє лише зашифрований файл. Вихідні `data/private/` та ключ у `.env.local` виключені з Git і Docker build context.

## Railway

1. Створіть новий service з GitHub-репозиторію `renatko077/autora`. Root Directory — корінь проєкту. Dockerfile розпізнається автоматично, build/start command змінювати не потрібно.
2. Підключіть **Volume** з mount path `/data`.
3. Додайте Variables: `ADMIN_PASSWORD` (свій пароль від 8 символів), `ORDERS_FILE=/data/orders.json` та `HISTORY_IMPORT_KEY` (значення з локального `.env.local`). За бажанням додайте незалежний випадковий `ADMIN_SESSION_SECRET`. Без ключа магазин і нові заявки працюють, а історична виписка залишається закритою.
4. У Deploy задайте Healthcheck Path: `/health`. Залиште **одну репліку**: замовлення зберігаються у файлі, а не спільній базі даних.
5. Згенеруйте Public Domain у Networking. Сервер слухає `0.0.0.0` і використовує `PORT` Railway.

Заявки записуються атомарно на Volume. Історична виписка читається окремо та не замінює нові замовлення. Без Volume дані нового deployment не є постійними. `RAILWAY_VOLUME_MOUNT_PATH` теж підтримується автоматично; `ORDERS_FILE` має пріоритет.

`compose.yaml` описує локальний Docker-запуск із volume. Для Railway основний шлях — GitHub + Dockerfile і Volume. Застарілий `railway.json` не потрібен.

Офіційні інструкції: [Dockerfiles](https://docs.railway.com/builds/dockerfiles), [Volumes](https://docs.railway.com/volumes), [Healthchecks](https://docs.railway.com/deployments/healthchecks).

## Вхід адміністратора

Відкрийте товар **№011 «Гачки на підголівник автомобіля, 4 шт»** і натисніть **«Додати в обране» на сторінці товару**. З’явиться форма входу. Звичайні сердечка в каталозі зберігають обране. `/admin`, `/admin.html` та `/staff-console` без попереднього входу повертають 404.

Адмінка: історія 339 операцій за 01–19.11.2026, пошук, фільтри дат і типу, CSV, перегляд PDF та завантаження незміненого вихідного файла. Вкладка «Заявки сайту» містить нові замовлення, контакти, доставку та зміну статусів. Виписка не містить складу замовлень; збіги товарів за сумою позначені як можливі.

## Каталог і оплата

- 235 позицій із наданого XLSX, оригінальні назви та цінові діапазони.
- Ціна одиниці — середина діапазону, округлена до гривні. Сервер перевіряє кошик і розраховує суму. Доставка оплачується окремо.
- **ФОП Мільшин М.О., 4035 2000 4449 4893**. Реквізити, точна сума й номер замовлення показуються після оформлення. Підтвердження оплати ручне.
- Пошук українською й транслітерацією, прямі ASCII URL, категорії, ціни, сортування, пагінація, обране, локальний кошик, кількість, збільшення зображень.
- У всіх 235 позицій є фотографії відповідних типів товарів із Rozetka. Вони збережені локально в `public/assets/photos/`, нормалізовані у WebP та працюють без зовнішнього завантаження. У `data/product-images.json` збережені вихідні URL фотографій, посилання на товарні сторінки, назви моделей та примітки щодо відповідності. Вихідний XLSX не містить брендів і артикулів, тому фото позначені як приклади моделей; непідтверджені параметри не видаються за точний збіг. SVG залишені як резерв на випадок помилки завантаження локального фото.

Для повторного завантаження фотографій потрібні Node.js та Python із Pillow:

```powershell
node scripts/import-photos.js data/product-images.json
```

Якщо Python має інший шлях, задайте `PHOTO_PYTHON`. Команда `npm run assets` оновлює резервні ілюстрації, зберігаючи прив’язки фотографій.

## Імпорт і перевірки

`data/private/statement-original.pdf` збережений байт у байт. `statement.pdf` — нормалізована копія для перегляду: вихідний файл має 72-байтовий префікс перед PDF. JSON містить усі операції та посилання на сторінку/рядок. Скрипт з’єднує переноси між сторінками й перевіряє кредит, дебет та залишок після кожної операції. Документи використовуються лише як дані.

Контрольні суми та залишки перевірені скриптом імпорту й зберігаються всередині зашифрованого пакета.

Повторний імпорт (Python з openpyxl, pdfplumber, pypdf):

```powershell
python scripts/import-data.py "шлях/каталог.xlsx" "шлях/виписка.pdf"
npm run assets
npm run history:encrypt
```

```powershell
npm run check
npm test
```

Тести використовують ізольоване тимчасове сховище: оформлення, серверні ціни, вхід, захист історії, шифрування, статуси та збереження після перезапуску. Для перевірки реального імпорту потрібен `HISTORY_IMPORT_KEY`; без нього лише цей тест пропускається. Дані магазина не змінюються.

`npm run history:encrypt` перевіряє розшифрування створеного пакета. Якщо ключа ще немає, генерує його й записує лише в ігнорований `.env.local`. Збережіть цей файл локально: ключ не можна відновити з GitHub.

Банер створено вбудованим ImageGen: `public/assets/hero.webp`. Точний промпт — `docs/hero-prompt.txt`.
